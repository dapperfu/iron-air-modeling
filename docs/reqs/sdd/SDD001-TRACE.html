    1. Source layout and clean baseline

     UID: SEC-SDD-SRC
    This Software Design Document (SDD) describes how ironair maps the patented
    iron-air plant onto Python packages, DynamicComponent classes, and algebraic
    versus dynamic state partitions. Physical geometry and chemistry come from
    US12308414B2 (device architectures for metal-air batteries) and EP4602674A1
    (electrode configurations for iron-air electrochemical systems). This SDD does
    not implement a second reaction network besides ironair.chemistry.
    • IA-SYS-001
      1.1. Python package UID: IA-SYS-001 STATUS: Active RELATIONS (Child):
      • IA-IRS-001 Public package imports
      • IA-SDD-001 Source layout
      • IA-SDD-005 Clean Python baseline
      • IA-REQ-001 StrictDoc source of truth
      • IA-TD-001 Package import test
      STATEMENT: The software SHALL be implemented as an installable Python package named ironair.

      All public APIs SHALL be importable using:

      import ironair
      from ironair import constants
      from ironair import chemistry
      from ironair import components
      from ironair import simulation
      from ironair import scenarios
      from ironair import plotting

      The implementation SHALL use a standard src/ package layout.

      The project SHALL provide editable installation using:

      pip install -e ".[dev,notebooks]"
       RATIONALE: A single installable package is the integration boundary for notebooks, tests, and
      coupled simulation of the patented iron-air plant. The SDRS src/ layout takes
      precedence over the generic no-src-directory Cursor rule for this project.
       COMMENT: Package ironair installs in a virtual environment. The listed imports succeed after
      pip install -e ".[dev,notebooks]" or the equivalent uv installation.

    IA-SDD-005
    1.2. Clean Python baseline UID: IA-SDD-005 STATUS: Active RELATIONS (Parent):
    • IA-SYS-001 Python package
    STATEMENT: This Python package is a new baseline. It SHALL NOT import, translate, or recover
    governing equations from prior MATLAB or Simulink implementations.

    Patent text SHALL be paraphrased into parameter metadata and requirement
    statements. Governing equations SHALL be implemented from the shared chemistry
    and component protocols, not by copying copyrighted patent prose into source.
     COMMENT: Source tree contains no .m or .slx physics. Chemistry and component modules implement
    the SDRS reaction set and ODE protocol directly.

    2. Component protocol and chemistry ownership

     UID: SEC-SDD-PROTO
    • IA-ODE-001
      4.1. Common component protocol UID: IA-ODE-001 STATUS: Active RELATIONS (Parent):
      • IA-SYS-003 ODE-based components
      RELATIONS (Child):
      • IA-IRS-002 RHS signature
      • IA-SDD-002 Dynamic component base
      • IA-TD-005 RHS determinism test
      STATEMENT: Every dynamic component SHALL implement rhs(self, t, y, inputs, context).

      The RHS SHALL be deterministic for a fixed state, time, input, and parameter configuration.

      It SHALL NOT modify component state through hidden side effects.
       COMMENT: Repeated rhs evaluations with identical arguments return identical arrays. Component
      parameter objects are unchanged after rhs.
    IA-SDD-002
    2.1. Dynamic component base UID: IA-SDD-002 STATUS: Active RELATIONS (Parent):
    • IA-ODE-001 Common component protocol
    STATEMENT: All physical components SHALL implement ironair.ode.protocol.DynamicComponentProtocol
    and MAY inherit ironair.ode.component.DynamicComponent for shared validation.

    rhs(t, y, inputs, context) SHALL be a pure function of its arguments for a fixed
    parameter configuration.

    Architecture flags (floating ORR, stacked submerged ORR, interdigitated OER,
    DRI bed, spiral, pleated) SHALL be parameters, not hidden rhs mutation.
     COMMENT: Protocol checks and unit tests cover every registered component class.
    • IA-SYS-004
      7.2. Shared component models UID: IA-SYS-004 STATUS: Active RELATIONS (Child):
      • IA-SDD-003 Shared chemistry ownership
      STATEMENT: Individual component simulations and the integrated battery SHALL use the same
      implementation.

      The system SHALL NOT contain separate, simplified physics solely for Jupyter
      examples.

      Reduced-order versions MAY be implemented, but SHALL be explicitly identified and
      tested against the corresponding higher-fidelity models.

      Patent architecture options (floating versus submerged ORR, planar versus
      interdigitated OER, bifunctional versus dual cathode) SHALL be selected by
      configuration flags on the shared components, not by forked governing equations.
       COMMENT: Notebooks import ironair and do not define replacement governing equations for
      production physics. Reduced-order models are named with a reduced_order flag or
      class name and have comparison tests.
    IA-SDD-003
    2.2. Shared chemistry ownership UID: IA-SDD-003 STATUS: Active RELATIONS (Parent):
    • IA-SYS-004 Shared component models
    STATEMENT: Electrode components SHALL obtain stoichiometric rates from ironair.chemistry rather
    than embedding a second reaction network.

    Iron conversion Fe / Fe(OH)2 / Fe3O4, ORR, OER, and HER SHALL use the capacities
    and half-reactions of IA-SYS-020 (EP4602674A1 [0042]-[0044]; US12308414B2 ORR
    four-electron reaction). Faraday mapping SHALL convert electrode current to molar
    rate.
     COMMENT: Iron, ORR, OER, and HER rate mapping uses ReactionNetwork.S and Faraday conversion.
    • IA-SYS-003
      7.1. ODE-based components UID: IA-SYS-003 STATUS: Active RELATIONS (Child):
      • IA-SDD-004 Algebraic versus dynamic states
      • IA-ODE-001 Common component protocol
      • IA-FE-001 Iron electrode ODE
      STATEMENT: Every physical component SHALL expose a dynamic ODE model.

      Each component SHALL explicitly define: state vector, state units, initial
      conditions, input variables, output variables, governing differential equations,
      algebraic constitutive relations, physical parameters, boundary conditions,
      conservation residuals, numerical constraints, and associated StrictDoc
      requirement IDs.

      Every component SHALL provide a rhs() method returning state derivatives.

      The generic mathematical representation SHALL be:

      dx/dt = f(t, x, inputs, parameters)

      Where required:

      0 = g(t, x, algebraic_variables, inputs, parameters)

      Algebraic variables SHALL be solved consistently during RHS evaluation or through
      a supported DAE backend.

      An artificial time constant SHALL NOT be introduced solely to make an instantaneous
      physical relation appear dynamic.

      Passive structures, such as current collectors, SHALL possess actual dynamic states
      where justified, such as temperature. Their instantaneous electrical resistance
      SHALL remain an algebraic relation.

      Patent-derived algebraic laws SHALL include Ohmic drop, hydraulic orifice and
      equalized stacked-ORR pressure drop, Nernst potential, and Faraday mapping of
      current to reaction rate.
       COMMENT: Every DynamicComponent publishes StateSpec metadata and a deterministic
      rhs(t, y, inputs, context). Algebraic electrical resistance is not converted into
      a fake lag state.
    IA-SDD-004
    2.3. Algebraic versus dynamic states UID: IA-SDD-004 STATUS: Active RELATIONS (Parent):
    • IA-SYS-003 ODE-based components
    STATEMENT: Instantaneous constitutive laws (Ohmic drop, hydraulic orifice flow at a fixed
    position, Nernst potential, stacked-ORR equal pressure drop of US12308414B2
    Claim 1, Faraday current-to-rate maps) SHALL be algebraic.

    Dynamic states SHALL represent stored mass, charge, thermal energy, momentum, or
    explicit controller memory, including iron phase inventories, electrolyte
    species, gas pockets, HER/OER bubble holdup, and controller modes.

    Artificial lag SHALL NOT be added to algebraic laws.
     COMMENT: CurrentCollector resistance is algebraic. CurrentCollector temperature is dynamic.
    Equalized ORR stack pressure drop is algebraic in geometry and flow.
    SEC-SDD-MAP

    3. Mapping patented architectures onto components

     UID: SEC-SDD-MAP
    US12308414B2 Claim 1 stacked submerged ORR is IronAirCell plus GasDiffusionLayer
    plus AirSystem with a vertical stack of ORR sections. EP4602674A1 Claim 1
    channeled iron plus interdigitated OER is IronElectrode plus OxygenEvolution with
    channel geometry parameters. Dual-electrode switching is SupervisoryController
    mode plus algebraic electrical connection, not a second chemistry module.
    • IA-SYS-008
      2.3. Dual-electrode charge and discharge paths UID: IA-SYS-008 STATUS: Active RELATIONS (Parent):
      • IA-SYS-002 Integrated physics simulation
      RELATIONS (Child):
      • IA-SDD-006 Dual-electrode electrical design
      • IA-SYS-010 Separate ORR and OER electrodes
      • IA-CEL-001 Complete cell ODE
      • IA-CTL-001 Supervisory control dynamics
      • IA-TD-007 Dual-electrode switch test
      STATEMENT: During charge the model SHALL electrically connect the iron electrode to the OER
      electrode and a power source so that iron species are reduced toward metallic
      Fe(0).

      During discharge the model SHALL electrically connect the iron electrode to the
      ORR electrode and a load so that metallic iron is oxidized toward higher-valence
      species including Fe(OH)2 and Fe3O4.

      A mode switch SHALL select charge versus discharge electrical paths as in
      EP4602674A1 [0049] switch 116 and US12308414B2 FIGS. 5A-5B toggle switch 550.

      OER and ORR electrodes SHALL be allowed to be electrically separated so that the
      ORR electrode is not exposed to high OER operating potentials that can damage or
      oxidize the ORR electrode (US12308414B2 FIGS. 5A-5B).
       RATIONALE: EP4602674A1 [0048]-[0049] and US12308414B2 dual-cathode architecture. Independent
      OER/ORR materials and geometries are separately optimized (US12308414B2).
       COMMENT: The supervisory controller implements the switch as a discrete operating mode, not
      as a hidden mutation of plant parameters.
    IA-SDD-006
    3.1. Dual-electrode electrical design UID: IA-SDD-006 STATUS: Active RELATIONS (Parent):
    • IA-SYS-008 Dual-electrode charge and discharge paths
    STATEMENT: IronAirCell SHALL expose separate ORR and OER electrical ports. SupervisoryController
    SHALL connect iron-OER-source in charge and iron-ORR-load in discharge
    (EP4602674A1 [0049]; US12308414B2 FIGS. 5A-5B).

    When isolated, ORR potential SHALL NOT be forced to the OER operating potential.
    Bifunctional single-air-electrode mode SHALL be an explicit reduced-order flag.
     RATIONALE: Protects carbon/PTFE ORR layers from OER potentials (US12308414B2). Matches
    EP4602674A1 switch 116.
    • IA-SYS-015
      4.1. Channeled iron electrode with interdigitated OER UID: IA-SYS-015 STATUS: Active RELATIONS (Parent):
      • IA-SYS-002 Integrated physics simulation
      RELATIONS (Child):
      • IA-SDD-007 Iron electrode geometric modes
      • IA-SYS-016 Channel and OER projection geometry

      STATEMENT: The system SHALL model an iron electrode in contact with an anode current collector
      and comprising a plurality of channels; an ORR electrode with a first surface
      facing the channels and an opposing second surface in contact with air; an OER
      electrode interdigitated with the channels, with at least a portion of the OER
      disposed within the channels in a direction perpendicular to the ORR plane; and
      electrolyte in contact with the iron electrode, the ORR first surface, the
      channels, and the OER electrode.

      This configuration SHALL be the default representation of EP4602674A1 Claim 1
      (FIG. 2).
       RATIONALE: EP4602674A1 Claim 1 and [0051]-[0058]. Channels carry ionic current while denser
      ribs carry electronic current, decoupling porosity trade-offs ([0050]).
    IA-SDD-007
    3.2. Iron electrode geometric modes UID: IA-SDD-007 STATUS: Active RELATIONS (Parent):
    • IA-SYS-015 Channeled iron electrode with interdigitated OER
    STATEMENT: IronElectrode SHALL implement at least these named geometric modes:

    - packed DRI pellet bed (US12308414B2 Claim 18);
    - planar porous electrode (EP4602674A1 FIG. 1 control);
    - channeled rib-and-spine electrode (Claim 1, FIG. 2);
    - discrete anode array (Claim 20);
    - spiral with current collector (Claim 70);
    - pleated electrode (Claim 77).

    Mode-specific parameters SHALL include loading 1-7 g Fe/cm2, electrolyte volume
    fraction 0.5-0.9, channel length/width/spacing, ChanFrac, and spine/rib porosity.
    • IA-SYS-009
      3.1. Submerged stacked ORR with depth-equalized pressure drop UID: IA-SYS-009 STATUS: Active RELATIONS (Parent):
      • IA-SYS-002 Integrated physics simulation
      RELATIONS (Child):
      • IA-SDD-008 ORR geometric modes
      • IA-SCN-PAT-STACKORR Submerged stacked ORR equal pressure drop
      • IA-TD-008 Stacked ORR equal pressure-drop test
      • IA-TP-005 Architecture verification objectives
      STATEMENT: The system SHALL support a submerged ORR electrode comprising a series of discrete
      ORR electrode sections arranged vertically in a stack below the electrolyte
      surface.

      Each discrete ORR section SHALL have geometry that can vary with depth below the
      electrolyte surface.

      The air-path model SHALL be able to impose equal pressure drop across each stacked
      ORR section in the depth direction.

      This configuration SHALL be the default representation of US12308414B2 Claim 1.
       RATIONALE: US12308414B2 Claim 1. Detailed description FIGS. 25A-36B, 57-58, and 35A-35C
      describe stacked-core / distillation-column ORR layers with depth-dependent bubble
      thickness, baffles, and cascading air.
       COMMENT: Equal pressure drop is an algebraic hydraulic constitutive law, not an artificial
      dynamic lag (IA-SYS-003).
    IA-SDD-008
    3.3. ORR geometric modes UID: IA-SDD-008 STATUS: Active RELATIONS (Parent):
    • IA-SYS-009 Submerged stacked ORR with depth-equalized pressure drop
    STATEMENT: OxygenReduction and GasDiffusionLayer SHALL implement floating, vertical
    natural-air-breathing, inverse box/tube, stacked submerged equal-dP, wavy/rippled,
    helical, and coaxial-core modes listed in IA-SYS-012.

      3.3. Stackable vessel and secondary containment UID: IA-SYS-011 STATUS: Active RELATIONS (Parent):

      STATEMENT: The enclosure model SHALL represent a stackable vessel that supports ORR, OER,
      metal electrode, and electrolyte and is configured to self-stack on other vessels
      (US12308414B2 Claim 3).

      The vessel SHALL be modelable as a double-walled container with an inner wall

      for thermal-management fluid, electrical isolation, thermal mass, or temporary
      electrolyte hold during maintenance (US12308414B2 FIGS. 1E-1F).

      reduced-order containment option.
       RATIONALE: US12308414B2 Claim 3 and vessel description. Self-stacking increases plant power

    • IA-SYS-005
      7.3. Simulation fidelity UID: IA-SYS-005 STATUS: Active RELATIONS (Child):
      • IA-SDD-010 Spatial discretization of thick electrodes
      STATEMENT: The software SHALL support lumped ODE models, spatially discretized ODE models,
      coupled differential-algebraic models, reduced-order dynamic models, and fully
      integrated system simulations.

      Spatially distributed PDE formulations SHALL be discretized using finite-volume or
      finite-difference methods to produce systems of ODEs or DAEs.

      Through-plane ionic gradients in thick iron electrodes and oxygen profiles in GDL
      and stacked ORR columns SHALL be representable by spatial discretization when
      high-fidelity mode is selected (EP4602674A1 [0046]-[0047]; US12308414B2 stacked
      ORR).
       COMMENT: CoupledSystem accepts lumped and spatially discretized components. Spatial
      components document their discretization method and node count.
    IA-SDD-010
    3.5. Spatial discretization of thick electrodes UID: IA-SDD-010 STATUS: Active RELATIONS (Parent):
    • IA-SYS-005 Simulation fidelity
    STATEMENT: When high-fidelity mode is selected, IronElectrode SHALL discretize through-plane
    or in-plane ionic path length so that front-versus-back HER competition of
    EP4602674A1 [0046]-[0047] is representable.

    Interdigitated OER SHALL shorten the modeled ionic path to the entire iron area
    relative to planar OER at the same loading (FIGS. 19-24).
