    SEC-SSS1-REQ

    1. Requirements management

    UID: SEC-SSS1-REQ
    STATEMENT: This document specifies foundation, chemistry, ODE, notebook, and verification
    requirements for ironair. Chemical stoichiometry, capacities, electrolyte
    compositions, and kinetics domains are taken from US12308414B2 and EP4602674A1.
    Software tests verify implementation against these statements; they do not
    validate the patents experimentally.
    IA-REQ-001
    1.1. StrictDoc source of truth
    UID: IA-REQ-001
    STATUS: Active
    RELATIONS (Parent):
    • IA-SYS-001 Python package
    STATEMENT: All requirements SHALL be maintained in StrictDoc .sdoc files.

    Markdown SHALL be used for supplementary explanatory design documents but SHALL NOT
    replace the authoritative requirements database.
    COMMENT: Every IA-* UID exists in reqs/**/*.sdoc. CI fails if a source @relation UID is missing
    from the StrictDoc database.
    IA-REQ-002
    1.2. Requirement identifiers
    UID: IA-REQ-002
    STATUS: Active
    STATEMENT: Each requirement SHALL possess a permanent unique ID.

    Required prefixes: IA-SYS, IA-REQ, IA-CON, IA-CHM, IA-FE, IA-HER, IA-ORR, IA-OER,
    IA-GDL, IA-ELY, IA-SEP, IA-COL, IA-CEL, IA-THM, IA-AIR, IA-FLD, IA-HEX, IA-STK,
    IA-MOD, IA-ENC, IA-DC, IA-CNV, IA-INV, IA-TRF, IA-GRD, IA-CTL, IA-EST, IA-DEG,
    IA-FLT, IA-ODE, IA-NBK, IA-PLT, IA-TST, IA-DOC.

    Patent-mapped system requirements live under IA-SYS in DOC-SRS001 (US12308414B2
    Claims 1-18 and EP4602674A1 Claims 1-89). Component prefixes SHALL be used for
    the corresponding physical models of those claims.
    COMMENT: UID uniqueness is verified by tests. All required prefixes appear in the requirements tree.
    IA-REQ-003
    1.3. Function-level traceability
    UID: IA-REQ-003
    STATUS: Active
    STATEMENT: Every public physics, control, solver, plotting, and scenario function SHALL contain a
    StrictDoc @relation marker.

    A function implementing several requirements SHALL contain separate relation markers
    for every applicable requirement.

    Internal helper functions SHALL be traceable to the applicable implementation requirements.

    The traceability system SHALL identify Requirement -> Python Function -> Test -> Notebook Scenario.
    COMMENT: CI greps @relation(UID, scope=function) in src/ironair and maps each implementation
    requirement to at least one function.
    IA-REQ-004
    1.4. Bidirectional traceability
    UID: IA-REQ-004
    STATUS: Active
    RELATIONS (Child):
    • IA-TD-006 Traceability test
    STATEMENT: CI SHALL verify that every implementation requirement has an associated function,
    every required function exists, every required function is covered by tests,
    every documented scenario has a notebook, every required notebook executes successfully,
    all source-level requirement references resolve to valid StrictDoc UIDs, and every
    requirements-to-source reference identifies an existing Python source element.
    COMMENT: tests/test_requirements_traceability.py fails the build on missing UIDs, missing
    functions, missing tests, or dangling file relations.
    IA-REQ-005
    1.5. Requirement verification
    UID: IA-REQ-005
    STATUS: Active
    STATEMENT: Every physical requirement SHALL specify acceptance criteria that can be objectively tested.

    Compliance SHALL be verified through unit tests, integration tests, conservation checks,
    numerical convergence tests, and documented model validation.

    Passing software tests SHALL NOT be represented as physical validation against experimental hardware.
    COMMENT: Physical requirements include ACCEPTANCE_CRITERIA. Validation status is tracked separately
    from software verification in ironair.validation. Patent claims are traced by UID
    and source citation, not by copying claim text as a test oracle.
    SEC-SSS1-CON

    2. Constants, parameters, and property models

    UID: SEC-SSS1-CON
    STATEMENT: US12308414B2 defines room temperature as 25 C and standard temperature and
    pressure as 25 C and 1 atm, with "about" meaning plus or minus 10 percent or
    instrument error, whichever is larger. EP4602674A1 simulations use 6 M KOH at
    303 K. Property models SHALL cover those reference states.
    IA-CON-001
    2.1. Constants module
    UID: IA-CON-001
    STATUS: Active
    RELATIONS (Child):
    • IA-TD-002 Constants immutability test
    STATEMENT: Implement src/ironair/constants.py providing F_C_MOL, R_J_MOL_K, T_REF_K, P_REF_PA,
    M_FE_KG_MOL, M_O2_KG_MOL, M_H2O_KG_MOL, and M_KOH_KG_MOL.

    T_REF_K SHALL default to 298.15 K (25 C) and P_REF_PA to 101325 Pa (1 atm) to
    match US12308414B2 standard ambient temperature and pressure. A 303 K property
    set SHALL be available for EP4602674A1 simulation conditions.

    Fundamental constants SHALL be immutable.
    COMMENT: from ironair import constants succeeds. Named constants match CODATA/IUPAC values
    within documented precision. Assignment to module constants raises an error or is
    rejected by typing/runtime freeze.
    IA-CON-002
    2.2. Parameter definitions
    UID: IA-CON-002
    STATUS: Active
    STATEMENT: Every component SHALL use explicit, typed parameter objects.

    Parameters SHALL include name, value, SI unit, physical meaning, valid range,
    source classification, literature reference when available, uncertainty when available,
    and calibration status.

    Parameter categories SHALL distinguish fundamental constant, literature value,
    experimental measurement, engineering design assumption, calibrated coefficient,
    and unverified placeholder.

    Patent-disclosed values (electrolyte molarity, channel lengths, iron loading,
    pO2 windows, theoretical mAh/g) SHALL be tagged as literature value with the
    patent number and claim or paragraph in the literature-reference field. They
    SHALL NOT be tagged as experimental measurement unless an independent hardware
    campaign is recorded.
    COMMENT: PhysicalParameter dataclass enforces required fields and rejects out-of-range values.
    Unverified placeholders are queryable via calibration_status.
    IA-CON-003
    2.3. Property models
    UID: IA-CON-003
    STATUS: Active
    RELATIONS (Parent):
    • IA-SYS-021 Electrolyte composition and pH domain
    STATEMENT: Implement concentration- and temperature-dependent properties for KOH conductivity,
    KOH density, KOH viscosity, KOH heat capacity, KOH water activity, dissolved oxygen
    solubility, oxygen diffusivity, gas-phase diffusivity, iron conductivity, thermal
    conductivity, reaction rate constants, and electrochemical exchange-current densities.

    Property models SHALL enforce their valid domains.

    KOH molarity domain SHALL include the patented compositions 5 M to 11 M hydroxide,
    including 6 M KOH, 5.5 M KOH + 0.5 M LiOH, 6 M NaOH, 5 M NaOH + 1 M KOH, and
    7 M or greater hydroxide (US12308414B2 electrolyte examples; EP4602674A1
    [0231]-[0241]).
    COMMENT: Property functions raise a domain error outside documented T and concentration ranges
    and return finite SI values inside the range.
    SEC-SSS1-CHM

    3. Shared iron-air chemistry (US12308414B2 and EP4602674A1)

    UID: SEC-SSS1-CHM
    STATEMENT: EP4602674A1 Equations 1-2 and US12308414B2 air-electrode half-reactions are the
    stoichiometric source for ironair.chemistry. Elemental conservation is a software
    requirement; the patents supply the reaction identities and theoretical capacities.
    IA-CHM-001
    3.1. Stoichiometric reaction network
    UID: IA-CHM-001
    STATUS: Active
    RELATIONS (Parent):
    • IA-SYS-002 Integrated physics simulation
    STATEMENT: Implement a common chemical reaction network.

    Mathematical model:

    dn/dt = S @ r + B @ q

    Where S is the chemical stoichiometric matrix, r is the reaction-rate vector,
    B maps boundary flows to species inventories, and q is the boundary-flow vector.

    The reaction network SHALL enforce elemental conservation.
    COMMENT: For every reaction column, elemental composition @ S[:, j] is numerically zero.
    IA-CHM-002
    3.2. Iron conversion
    UID: IA-CHM-002
    STATUS: Active
    RELATIONS (Parent):
    • IA-SYS-020 Iron-air reaction set
    STATEMENT: Implement Fe + 2OH- <-> Fe(OH)2 + 2e- as EP4602674A1 [0042] Equation 1.

    Calculate reaction rates from electrode kinetics and Faraday's law.

    Theoretical first-step capacity SHALL be 960 mAh per gram of metallic Fe
    (EP4602674A1 [0043]). Net volume increase on discharge SHALL be accommodated in
    anode porosity rather than by creating unphysical inventory.
    RATIONALE: EP4602674A1 [0042]-[0043]. US12308414B2 identifies Fe and Fe-alloys (FeAl, FeZn,
    FeMg) as metal-electrode options; iron is the default LODES anode.
    COMMENT: Two electrons per iron atom. Faraday mapping r = i * A / (n * F) holds within solver tolerance.
    IA-CHM-003
    3.3. Magnetite formation
    UID: IA-CHM-003
    STATUS: Active
    RELATIONS (Parent):
    • IA-SYS-020 Iron-air reaction set
    STATEMENT: Implement configurable conversion between iron hydroxide and magnetite, including
    electron transfer and correct stoichiometry.

    The second discharge step SHALL correspond to further oxidation of Fe(OH)2 to
    Fe3O4 with theoretical capacity 320 mAh per gram of Fe (EP4602674A1 [0043]
    Equation 2). Charge SHALL reduce higher-valence iron species toward Fe(0)
    (EP4602674A1 [0049]).
    RATIONALE: EP4602674A1 [0042]-[0043], [0049]. Magnetite is the example higher-valence product
    on discharge through the dual-electrode load path.
    COMMENT: Default electrochemical path conserves Fe, O, H, and charge. A Schikorr chemical path
    may be enabled without inventing extra electrons.
    IA-CHM-004
    3.4. Oxygen reduction reaction
    UID: IA-CHM-004
    STATUS: Active
    RELATIONS (Parent):
    • IA-SYS-020 Iron-air reaction set
    STATEMENT: Implement O2 + 2H2O + 4e- -> 4OH- as the ORR discharge reaction of
    US12308414B2 (four-electron oxygen reduction at the gas-solid-electrolyte
    triple-phase boundary).

    ORR SHALL consume gaseous oxygen typically sourced from air and SHALL require
    triple-phase contact among O2, an electronically conductive solid, and
    electrolyte.
    RATIONALE: US12308414B2 detailed description of cathode 120 / GDE operation. EP4602674A1
    FIG. 1 ORR electrode 104 is the discharge positive.
    COMMENT: Four electrons per O2. OH- production matches Faraday's law.
    IA-CHM-005
    3.5. Oxygen evolution reaction
    UID: IA-CHM-005
    STATUS: Active
    RELATIONS (Parent):
    • IA-SYS-020 Iron-air reaction set
    STATEMENT: Implement 4OH- -> O2 + 2H2O + 4e- as the OER charge reaction on a dedicated
    OER electrode (US12308414B2 dual cathode; EP4602674A1 [0048]-[0049]).

    OER kinetics, catalyst state, and bubble generation SHALL be independent of ORR
    so that high OER potentials do not oxidize the ORR electrode when the electrodes
    are electrically separated (US12308414B2 FIGS. 5A-5B).
    RATIONALE: Dual-electrode configuration in both patents. EP4602674A1 Claim 11: OER as porous
    metal mesh plus oxygen-evolution catalyst (Ni, Ni-Fe, Mn oxide, Fe, NiOx,
    NiOx(OH)y, FeOx, FeOx(OH)y).
    COMMENT: OER is the reverse four-electron oxygen couple of ORR with independent kinetics.
    IA-CHM-006
    3.6. Hydrogen evolution reaction
    UID: IA-CHM-006
    STATUS: Active
    RELATIONS (Parent):
    • IA-SYS-020 Iron-air reaction set
    STATEMENT: Implement 2H2O + 2e- -> H2 + 2OH- as the parasitic hydrogen evolution reaction
    that competes with iron recharge (EP4602674A1 [0044], [0047]).

    HER SHALL be favored at the electrode front when ionic path length to unreacted
    oxidized iron at the back is large. Channeled and interdigitated geometries
    SHALL reduce that path length and SHALL be able to increase coulombic efficiency
    relative to planar electrodes (EP4602674A1 FIGS. 19-21).
    RATIONALE: EP4602674A1 [0044]-[0050] and FIGS. 19-26. Water as HER reactant can be replenished
    while iron hydroxide at the back remains transport-limited.
    COMMENT: Two electrons per H2. Rate increases with more negative iron overpotential.
    IA-CHM-007
    3.7. Butler-Volmer kinetics
    UID: IA-CHM-007
    STATUS: Active
    RELATIONS (Child):
    • IA-TD-004 Butler-Volmer equilibrium test
    STATEMENT: Implement nonlinear electrode kinetics with exchange-current density, transfer coefficients,
    local overpotential, temperature, species activities, electrode surface area, and
    reaction availability.

    Exchange-current densities SHALL be temperature- and concentration-dependent
    within the patented alkaline domain. Interdigitated OER SHALL be allowed to
    lower effective ionic overpotential relative to planar OER at the same loading
    (EP4602674A1 FIGS. 19-24).
    COMMENT: Zero overpotential yields zero net Faradaic current at unit activities. Current is
    odd in overpotential for symmetric coefficients.
    IA-CHM-008
    3.8. Nernst potentials
    UID: IA-CHM-008
    STATUS: Active
    STATEMENT: Calculate equilibrium potentials using thermodynamically consistent activities and
    standard electrode-potential references.
    COMMENT: Nernst potentials shift (RT/nF) ln(activity quotient) relative to documented E0.
    IA-CHM-009
    3.9. Reaction thermodynamics
    UID: IA-CHM-009
    STATUS: Active
    STATEMENT: Calculate Gibbs free energy, reaction enthalpy, reaction entropy, equilibrium cell
    potential, reversible reaction heat, and irreversible reaction heat.
    COMMENT: E_eq = -DeltaG / (n F). Irreversible heat is eta * i * A. Reversible heat uses T * DeltaS.
    IA-CHM-010
    3.10. Chemistry conservation
    UID: IA-CHM-010
    STATUS: Active
    RELATIONS (Child):
    • IA-TST-001 Elemental conservation
    STATEMENT: The central chemistry module SHALL check iron atom conservation, oxygen atom conservation,
    hydrogen atom conservation, potassium conservation, carbon conservation, charge balance,
    electron transfer, and reaction stoichiometry.
    COMMENT: Elemental residual norms are below 1e-12 relative to characteristic inventory for
    closed-system reaction extents.
    IA-CHM-011
    3.11. Coulombic efficiency versus electrode architecture
    UID: IA-CHM-011
    STATUS: Active
    RELATIONS (Parent):
    • IA-SYS-015 Channeled iron electrode with interdigitated OER
    RELATIONS (Child):
    • IA-SCN-PAT-INTERDIG Interdigitated OER versus planar control
    • IA-TD-009 Interdigitated coulombic-efficiency trend test
    STATEMENT: The chemistry-to-electrode coupling SHALL report instantaneous coulombic charge
    efficiency as the fraction of charge current stored in intended iron reduction
    products rather than HER (EP4602674A1 [0044], FIGS. 19, 21, 23, 25).

    Planar, channeled, and interdigitated OER/iron layouts SHALL be comparable on
    the same ParameterSet. Interdigitated layouts SHALL be able to show higher
    coulombic efficiency and lower sensitivity of efficiency to areal loading than
    planar layouts, matching the qualitative simulation results of EP4602674A1
    FIGS. 19-24 at 6 M KOH, 303 K, initial rib porosity 0.6, example ChanFrac 0.4,
    w_rib 5 mm, and example loading 4 g Fe/cm2.
    RATIONALE: EP4602674A1 [0261]-[0280] and FIGS. 19-27. FIG. 27 experimental interdigitated
    cell showed an extended upper discharge voltage plateau versus planar control
    at matched loading, temperature, current, electrolyte, and ORR.
    SEC-SSS1-ODE

    4. ODE protocol, solvers, and multiscale execution

    UID: SEC-SSS1-ODE
    IA-ODE-001
    4.1. Common component protocol
    UID: IA-ODE-001
    STATUS: Active
    RELATIONS (Parent):
    • IA-SYS-003 ODE-based components
    RELATIONS (Child):
    • IA-IRS-002 RHS signature
    • IA-SDD-002 Dynamic component base
    • IA-TD-005 RHS determinism test
    STATEMENT: Every dynamic component SHALL implement rhs(self, t, y, inputs, context).

    The RHS SHALL be deterministic for a fixed state, time, input, and parameter configuration.

    It SHALL NOT modify component state through hidden side effects.
    COMMENT: Repeated rhs evaluations with identical arguments return identical arrays. Component
    parameter objects are unchanged after rhs.
    IA-ODE-002
    4.2. State definitions
    UID: IA-ODE-002
    STATUS: Active
    STATEMENT: Each component SHALL publish named state metadata and a validated state vector layout.

    State arrays SHALL be NumPy arrays.
    COMMENT: y0 size matches len(state_specs). Units and names are unique per component.
    IA-ODE-003
    4.3. Coupled solver
    UID: IA-ODE-003
    STATUS: Active
    RELATIONS (Child):
    • IA-IRS-003 CoupledSystem simulate interface
    STATEMENT: Implement ironair.simulation.CoupledSystem.

    The solver SHALL assemble component states into one global state vector, maintain a
    state-index map, resolve shared inputs and algebraic couplings, evaluate the coupled
    RHS, pass the assembled system to SciPy, detect numerical failures, and return state
    trajectories and diagnostics.
    COMMENT: simulate() returns a SimulationResult with t, y, names, and solver diagnostics.
    Failure of solve_ivp is reported rather than silently truncated.
    IA-ODE-004
    4.4. Stiff solvers
    UID: IA-ODE-004
    STATUS: Active
    STATEMENT: The default integrated system SHALL use a stiff-capable solver, normally SciPy BDF or Radau.

    Nonstiff component demonstrations MAY use RK45 or DOP853.
    COMMENT: CoupledSystem default method is BDF or Radau.
    IA-ODE-005
    4.5. Numerical robustness
    UID: IA-ODE-005
    STATUS: Active
    STATEMENT: The simulation SHALL include state-specific absolute tolerances, relative tolerances,
    Jacobian sparsity, event detection, hybrid mode transitions, nonnegative inventory
    checks, solver diagnostics, and energy and mass conservation residuals.
    COMMENT: SimulationResult exposes atol vector, events, conservation residuals, and solver status.
    IA-ODE-006
    4.6. Multiscale execution
    UID: IA-ODE-006
    STATUS: Active
    RELATIONS (Parent):
    • IA-SYS-007 Long-duration energy storage mission
    STATEMENT: The system SHALL support millisecond, second, minute, hour, and multi-day simulation windows.

    Detailed electrochemical dynamics and long-duration grid dispatch SHALL be able to use
    different model fidelity settings while sharing the same physical parameter definitions.
    COMMENT: The same ParameterSet can be passed to detailed and reduced-order components.
    t_span may be [0, 1e-3] or [0, 7*86400] without changing parameter objects.
    LODES windows of 8 h, 100 h, 300 h, week-scale, and seasonal duration from
    US12308414B2 SHALL use the same ParameterSet with documented fidelity flags.

    SEC-SSS1-TST

    6. Verification, conservation, and reproducibility

    UID: SEC-SSS1-TST
    IA-TST-001
    6.1. Elemental conservation
    UID: IA-TST-001
    STATUS: Active
    RELATIONS (Parent):
    • IA-CHM-010 Chemistry conservation
    RELATIONS (Child):
    • IA-TD-003 Elemental conservation test
    STATEMENT: The stoichiometric network SHALL conserve chemical elements for every reaction.
    COMMENT: max(abs(element_matrix @ S)) < 1e-12.
    IA-TST-002
    6.2. Charge conservation
    UID: IA-TST-002
    STATUS: Active
    STATEMENT: Electrode currents, capacitive currents, and reaction rates SHALL obey conservation of charge.
    COMMENT: Sum of Faradaic, capacitive, and terminal currents is below 1e-9 A relative residual.
    IA-TST-003
    6.3. Energy conservation
    UID: IA-TST-003
    STATUS: Active
    STATEMENT: The coupled system SHALL account for electrical, chemical, thermal, and material-flow energy.
    COMMENT: Closed-system energy residual is reported and below documented tolerance for the adiabatic cell test.
    IA-TST-004
    6.4. Physical state validity
    UID: IA-TST-004
    STATUS: Active
    STATEMENT: The simulation SHALL reject or explicitly report invalid physical states including negative
    species inventory, nonphysical porosity, invalid electrolyte volume, nonphysical absolute
    temperature, invalid pressure, impossible oxygen consumption, and nonphysical cell voltage
    or current conditions.
    COMMENT: ironair.exceptions.InvalidPhysicalState is raised or recorded on invalid states.
    IA-TST-005
    6.5. Numerical convergence
    UID: IA-TST-005
    STATUS: Active
    STATEMENT: The system SHALL include solver tolerance refinement tests and, for spatial models,
    mesh refinement tests.
    COMMENT: Halving rtol reduces trajectory error against a tight-tolerance reference.
    IA-TST-006
    6.6. Model validation tracking
    UID: IA-TST-006
    STATUS: Active
    RELATIONS (Child):
    • IA-TP-002 Verification versus validation
    STATEMENT: Software verification SHALL be distinguished from model validation.

    Experimental calibration and independent physical validation SHALL be separately tracked.
    COMMENT: Parameter source_class and validation.ValidationRecord never treat unit-test pass as
    hardware validation.
    IA-TST-007
    6.7. Automated unit tests
    UID: IA-TST-007
    STATUS: Active
    RELATIONS (Child):
    • IA-TP-001 Phase-gate testing
    STATEMENT: Every exported physical calculation and dynamic component SHALL have automated pytest coverage.
    COMMENT: pytest coverage for src/ironair is at least 80 percent.
    IA-TST-008
    6.8. Component integration tests
    UID: IA-TST-008
    STATUS: Active
    STATEMENT: Every coupled component interface SHALL have integration tests verifying dimensions,
    units, and conservation.
    COMMENT: CoupledSystem with a cell plus thermal node conserves charge and reports unit-consistent outputs.
    IA-TST-009
    6.9. Notebook execution tests
    UID: IA-TST-009
    STATUS: Active
    STATEMENT: Every mandatory notebook SHALL execute from a clean kernel without manual intervention.
    COMMENT: pytest marker notebook executes required notebooks via nbclient.
    IA-TST-010
    6.10. Requirements coverage gate
    UID: IA-TST-010
    STATUS: Active
    RELATIONS (Child):
