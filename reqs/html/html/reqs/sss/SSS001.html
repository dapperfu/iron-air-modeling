    IA-REQ-001
    1. StrictDoc source of truth
    UID: IA-REQ-001
    STATUS: Active
    RELATIONS (Parent):
    • IA-SYS-001 Python package
    STATEMENT: All requirements SHALL be maintained in StrictDoc .sdoc files.

    Markdown SHALL be used for supplementary explanatory design documents but SHALL NOT
    replace the authoritative requirements database.
    COMMENT: Every IA-* UID exists in reqs/**/*.sdoc. CI fails if a source @relation UID is missing
    from the StrictDoc database.
    IA-REQ-002
    2. Requirement identifiers
    UID: IA-REQ-002
    STATUS: Active
    STATEMENT: Each requirement SHALL possess a permanent unique ID.

    Required prefixes: IA-SYS, IA-REQ, IA-CON, IA-CHM, IA-FE, IA-HER, IA-ORR, IA-OER,
    IA-GDL, IA-ELY, IA-SEP, IA-COL, IA-CEL, IA-THM, IA-AIR, IA-FLD, IA-HEX, IA-STK,
    IA-MOD, IA-ENC, IA-DC, IA-CNV, IA-INV, IA-TRF, IA-GRD, IA-CTL, IA-EST, IA-DEG,
    IA-FLT, IA-ODE, IA-NBK, IA-PLT, IA-TST, IA-DOC.
    COMMENT: UID uniqueness is verified by tests. All required prefixes appear in the requirements tree.
    IA-REQ-003
    3. Function-level traceability
    UID: IA-REQ-003
    STATUS: Active
    STATEMENT: Every public physics, control, solver, plotting, and scenario function SHALL contain a
    StrictDoc @relation marker.

    A function implementing several requirements SHALL contain separate relation markers
    for every applicable requirement.

    Internal helper functions SHALL be traceable to the applicable implementation requirements.

    The traceability system SHALL identify Requirement -> Python Function -> Test -> Notebook Scenario.
    COMMENT: CI greps @relation(UID, scope=function) in src/ironair and maps each implementation
    requirement to at least one function.
    IA-REQ-004
    4. Bidirectional traceability
    UID: IA-REQ-004
    STATUS: Active
    RELATIONS (Child):
    • IA-TD-006 Traceability test
    STATEMENT: CI SHALL verify that every implementation requirement has an associated function,
    every required function exists, every required function is covered by tests,
    every documented scenario has a notebook, every required notebook executes successfully,
    all source-level requirement references resolve to valid StrictDoc UIDs, and every
    requirements-to-source reference identifies an existing Python source element.
    COMMENT: tests/test_requirements_traceability.py fails the build on missing UIDs, missing
    functions, missing tests, or dangling file relations.
    IA-REQ-005
    5. Requirement verification
    UID: IA-REQ-005
    STATUS: Active
    STATEMENT: Every physical requirement SHALL specify acceptance criteria that can be objectively tested.

    Compliance SHALL be verified through unit tests, integration tests, conservation checks,
    numerical convergence tests, and documented model validation.

    Passing software tests SHALL NOT be represented as physical validation against experimental hardware.
    COMMENT: Physical requirements include ACCEPTANCE_CRITERIA. Validation status is tracked separately
    from software verification in ironair.validation.
    IA-CON-001
    6. Constants module
    UID: IA-CON-001
    STATUS: Active
    RELATIONS (Child):
    • IA-TD-002 Constants immutability test
    STATEMENT: Implement src/ironair/constants.py providing F_C_MOL, R_J_MOL_K, T_REF_K, P_REF_PA,
    M_FE_KG_MOL, M_O2_KG_MOL, M_H2O_KG_MOL, and M_KOH_KG_MOL.

    Fundamental constants SHALL be immutable.
    COMMENT: from ironair import constants succeeds. Named constants match CODATA/IUPAC values
    within documented precision. Assignment to module constants raises an error or is
    rejected by typing/runtime freeze.
    IA-CON-002
    7. Parameter definitions
    UID: IA-CON-002
    STATUS: Active
    STATEMENT: Every component SHALL use explicit, typed parameter objects.

    Parameters SHALL include name, value, SI unit, physical meaning, valid range,
    source classification, literature reference when available, uncertainty when available,
    and calibration status.

    Parameter categories SHALL distinguish fundamental constant, literature value,
    experimental measurement, engineering design assumption, calibrated coefficient,
    and unverified placeholder.
    COMMENT: PhysicalParameter dataclass enforces required fields and rejects out-of-range values.
    Unverified placeholders are queryable via calibration_status.
    IA-CON-003
    8. Property models
    UID: IA-CON-003
    STATUS: Active
    STATEMENT: Implement concentration- and temperature-dependent properties for KOH conductivity,
    KOH density, KOH viscosity, KOH heat capacity, KOH water activity, dissolved oxygen
    solubility, oxygen diffusivity, gas-phase diffusivity, iron conductivity, thermal
    conductivity, reaction rate constants, and electrochemical exchange-current densities.

    Property models SHALL enforce their valid domains.
    COMMENT: Property functions raise a domain error outside documented T and concentration ranges
    and return finite SI values inside the range.
    IA-CHM-001
    9. Stoichiometric reaction network
    UID: IA-CHM-001
    STATUS: Active
    RELATIONS (Parent):
    • IA-SYS-002 Integrated physics simulation
    STATEMENT: Implement a common chemical reaction network.

    Mathematical model:

    dn/dt = S @ r + B @ q

    Where S is the chemical stoichiometric matrix, r is the reaction-rate vector,
    B maps boundary flows to species inventories, and q is the boundary-flow vector.

    The reaction network SHALL enforce elemental conservation.
    COMMENT: For every reaction column, elemental composition @ S[:, j] is numerically zero.
    IA-CHM-002
    10. Iron conversion
    UID: IA-CHM-002
    STATUS: Active
    STATEMENT: Implement Fe + 2OH- <-> Fe(OH)2 + 2e-.

    Calculate reaction rates from electrode kinetics and Faraday's law.
    COMMENT: Two electrons per iron atom. Faraday mapping r = i * A / (n * F) holds within solver tolerance.
    IA-CHM-003
    11. Magnetite formation
    UID: IA-CHM-003
    STATUS: Active
    STATEMENT: Implement configurable conversion between iron hydroxide and magnetite, including
    electron transfer and correct stoichiometry.
    COMMENT: Default electrochemical path conserves Fe, O, H, and charge. A Schikorr chemical path
    may be enabled without inventing extra electrons.
    IA-CHM-004
    12. Oxygen reduction reaction
    UID: IA-CHM-004
    STATUS: Active
    STATEMENT: Implement O2 + 2H2O + 4e- -> 4OH-.
    COMMENT: Four electrons per O2. OH- production matches Faraday's law.
    IA-CHM-005
    13. Oxygen evolution reaction
    UID: IA-CHM-005
    STATUS: Active
    STATEMENT: Implement 4OH- -> O2 + 2H2O + 4e-.
    COMMENT: OER is the reverse four-electron oxygen couple of ORR with independent kinetics.
    IA-CHM-006
    14. Hydrogen evolution reaction
    UID: IA-CHM-006
    STATUS: Active
    STATEMENT: Implement 2H2O + 2e- -> H2 + 2OH-.
    COMMENT: Two electrons per H2. Rate increases with more negative iron overpotential.
    IA-CHM-007
    15. Butler-Volmer kinetics
    UID: IA-CHM-007
    STATUS: Active
    RELATIONS (Child):
    • IA-TD-004 Butler-Volmer equilibrium test
    STATEMENT: Implement nonlinear electrode kinetics with exchange-current density, transfer coefficients,
    local overpotential, temperature, species activities, electrode surface area, and
    reaction availability.
    COMMENT: Zero overpotential yields zero net Faradaic current at unit activities. Current is
    odd in overpotential for symmetric coefficients.
    IA-CHM-008
    16. Nernst potentials
    UID: IA-CHM-008
    STATUS: Active
    STATEMENT: Calculate equilibrium potentials using thermodynamically consistent activities and
    standard electrode-potential references.
    COMMENT: Nernst potentials shift (RT/nF) ln(activity quotient) relative to documented E0.
    IA-CHM-009
    17. Reaction thermodynamics
    UID: IA-CHM-009
    STATUS: Active
    STATEMENT: Calculate Gibbs free energy, reaction enthalpy, reaction entropy, equilibrium cell
    potential, reversible reaction heat, and irreversible reaction heat.
    COMMENT: E_eq = -DeltaG / (n F). Irreversible heat is eta * i * A. Reversible heat uses T * DeltaS.
    IA-CHM-010
    18. Chemistry conservation
    UID: IA-CHM-010
    STATUS: Active
    RELATIONS (Child):
    • IA-TST-001 Elemental conservation
    STATEMENT: The central chemistry module SHALL check iron atom conservation, oxygen atom conservation,
    hydrogen atom conservation, potassium conservation, carbon conservation, charge balance,
    electron transfer, and reaction stoichiometry.
    COMMENT: Elemental residual norms are below 1e-12 relative to characteristic inventory for
    closed-system reaction extents.
    IA-ODE-001
    19. Common component protocol
    UID: IA-ODE-001
    STATUS: Active
    RELATIONS (Parent):
    • IA-SYS-003 ODE-based components
    RELATIONS (Child):
    • IA-IRS-002 RHS signature
    • IA-SDD-002 Dynamic component base
    • IA-TD-005 RHS determinism test
    STATEMENT: Every dynamic component SHALL implement rhs(self, t, y, inputs, context).

    The RHS SHALL be deterministic for a fixed state, time, input, and parameter configuration.

    It SHALL NOT modify component state through hidden side effects.
    COMMENT: Repeated rhs evaluations with identical arguments return identical arrays. Component
    parameter objects are unchanged after rhs.
    IA-ODE-002
    20. State definitions
    UID: IA-ODE-002
    STATUS: Active
    STATEMENT: Each component SHALL publish named state metadata and a validated state vector layout.

    State arrays SHALL be NumPy arrays.
    COMMENT: y0 size matches len(state_specs). Units and names are unique per component.
    IA-ODE-003
    21. Coupled solver
    UID: IA-ODE-003
    STATUS: Active
    RELATIONS (Child):
    • IA-IRS-003 CoupledSystem simulate interface
    STATEMENT: Implement ironair.simulation.CoupledSystem.

    The solver SHALL assemble component states into one global state vector, maintain a
    state-index map, resolve shared inputs and algebraic couplings, evaluate the coupled
    RHS, pass the assembled system to SciPy, detect numerical failures, and return state
    trajectories and diagnostics.
    COMMENT: simulate() returns a SimulationResult with t, y, names, and solver diagnostics.
    Failure of solve_ivp is reported rather than silently truncated.
    IA-ODE-004
    22. Stiff solvers
    UID: IA-ODE-004
    STATUS: Active
    STATEMENT: The default integrated system SHALL use a stiff-capable solver, normally SciPy BDF or Radau.

    Nonstiff component demonstrations MAY use RK45 or DOP853.
    COMMENT: CoupledSystem default method is BDF or Radau.
    IA-ODE-005
    23. Numerical robustness
    UID: IA-ODE-005
    STATUS: Active
    STATEMENT: The simulation SHALL include state-specific absolute tolerances, relative tolerances,
    Jacobian sparsity, event detection, hybrid mode transitions, nonnegative inventory
    checks, solver diagnostics, and energy and mass conservation residuals.
    COMMENT: SimulationResult exposes atol vector, events, conservation residuals, and solver status.
    IA-ODE-006
    24. Multiscale execution
    UID: IA-ODE-006
    STATUS: Active
    STATEMENT: The system SHALL support millisecond, second, minute, hour, and multi-day simulation windows.

    Detailed electrochemical dynamics and long-duration grid dispatch SHALL be able to use
    different model fidelity settings while sharing the same physical parameter definitions.
    COMMENT: The same ParameterSet can be passed to detailed and reduced-order components.
    t_span may be [0, 1e-3] or [0, 7*86400] without changing parameter objects.
    IA-NBK-001
    25. Notebook development environment
    UID: IA-NBK-001
    STATUS: Active
    STATEMENT: All notebooks SHALL be located in notebooks/.

    All notebooks SHALL import numerical models from the installed ironair package.

    No notebook SHALL contain a separate replacement implementation of a battery physics model.
    COMMENT: Notebook AST/source scan finds no duplicate rhs or stoichiometric matrix definitions.

    26. Seaborn visualization
    UID: IA-NBK-002

    RELATIONS (Child):

    Matplotlib MAY be used for figure management, multi-axis plots, annotations, and
    specialized graphics.

    Plots SHALL include title, axis labels, physical units, legend where necessary,
    scenario identifier, and physical operating assumptions.
    COMMENT: Principal plotting helpers call seaborn and require title, xlabel, ylabel, and scenario_id.

    IA-TST-001
    32. Elemental conservation
    UID: IA-TST-001
    STATUS: Active
    RELATIONS (Parent):
    • IA-CHM-010 Chemistry conservation
    RELATIONS (Child):
    • IA-TD-003 Elemental conservation test
    STATEMENT: The stoichiometric network SHALL conserve chemical elements for every reaction.
    COMMENT: max(abs(element_matrix @ S)) < 1e-12.
    IA-TST-002
    33. Charge conservation
    UID: IA-TST-002
    STATUS: Active
    STATEMENT: Electrode currents, capacitive currents, and reaction rates SHALL obey conservation of charge.
    COMMENT: Sum of Faradaic, capacitive, and terminal currents is below 1e-9 A relative residual.
    IA-TST-003
    34. Energy conservation
    UID: IA-TST-003
    STATUS: Active
    STATEMENT: The coupled system SHALL account for electrical, chemical, thermal, and material-flow energy.
    COMMENT: Closed-system energy residual is reported and below documented tolerance for the adiabatic cell test.
    IA-TST-004
    35. Physical state validity
    UID: IA-TST-004
    STATUS: Active
    STATEMENT: The simulation SHALL reject or explicitly report invalid physical states including negative
    species inventory, nonphysical porosity, invalid electrolyte volume, nonphysical absolute
    temperature, invalid pressure, impossible oxygen consumption, and nonphysical cell voltage
    or current conditions.
    COMMENT: ironair.exceptions.InvalidPhysicalState is raised or recorded on invalid states.
    IA-TST-005
    36. Numerical convergence
    UID: IA-TST-005
    STATUS: Active
    STATEMENT: The system SHALL include solver tolerance refinement tests and, for spatial models,
    mesh refinement tests.
    COMMENT: Halving rtol reduces trajectory error against a tight-tolerance reference.

    UID: IA-TST-006
    STATUS: Active
    RELATIONS (Child):
